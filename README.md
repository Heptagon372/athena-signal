# 아테나 시그널 (Athena Signal) v1.0

**코스피 · 코스닥 · 미국** 종목을 대상으로, 기술적 지표 19종 + 국내외 뉴스 감성 + 커뮤니티 여론을
종합해 "이 종목이 오를지 내릴지"를 확률(%)로 예측하고, 만기가 지난 예측을 실제 가격과 대조해
스스로 채점·학습하는 분석 콘솔입니다.

- **백엔드** FastAPI (Python) — 분석 엔진 · 인증 · 데이터
- **프론트엔드** Next.js 16 (React 19) — 페이지별 독립 라우트
- **계정별 데이터** 예측 기록 · 성적표 · 모의투자 계좌를 사용자마다 분리

⚠️ **중요**: 이 시스템이 만드는 확률은 검증된 투자 조언이 아니라 실험적 휴리스틱 지표입니다.
실제 투자 판단에 단독으로 사용하지 마세요.

## 실행 방법

**`아테나.bat` 더블클릭 → `[1] 시작`.** 백엔드(분석 엔진)와 프론트엔드(웹)를 함께 띄우고
브라우저를 엽니다. 실행·설정·업로드는 모두 이 콘솔 한 창에서 합니다 (`python athena.py` 와 같습니다).

```
웹      http://localhost:3000   여기로 접속하세요 (Next.js)
백엔드  http://localhost:8000   분석 · API (FastAPI)
```

콘솔에서는 화살표로 고르고 Enter, 또는 글쇠를 바로 누릅니다.

| 글쇠 | 항목 | 하는 일 |
|---|---|---|
| `1` | 시작 | 백엔드 + 웹을 켜고 브라우저를 엽니다 |
| `2` | 상태 확인 | 무엇이 켜져 있는지만 봅니다 (서버를 건드리지 않음) |
| `3` | 업데이트 | 코드를 고친 뒤 서버만 다시 올립니다 |
| `4` | 강제 업데이트 | 체결 대기 주문이 있어도 진행합니다 |
| `5` `6` | 올리기 · 받아오기 | GitHub 에 저장 / 다른 PC 의 최신 코드 받기 |
| `7` `8` `9` | API 키 · 구글 로그인 · 자동매매 | 설정 (`api_keys.json` 에 저장) |
| `B` | EXE 만들기 | `dist\AthenaSignal.exe` 로 굽습니다 |

윗줄에 백엔드·웹이 켜져 있는지, git 에 안 올린 변경이 몇 건인지, 자동매매가
모의인지 실전인지가 늘 보입니다.

**8000번으로 들어와도 괜찮습니다.** 예전 주소나 북마크(`localhost:8000/#paper` 등)로 접속하면
3000번의 해당 화면으로 자동으로 넘어갑니다. 해시(`#paper`)는 서버로 전송되지 않으므로,
브라우저에서 경로로 바꿔 넘겨줍니다.

| 들어온 주소 | 도착 |
|---|---|
| `:8000/` · `:8000/#analysis` | `:3000/` |
| `:8000/#score` · `:8000/score` | `:3000/score` |
| `:8000/#paper` · `:8000/paper` | `:3000/paper` |

웹(3000번)이 꺼져 있으면 흰 화면 대신 **어떻게 켜는지 안내하는 페이지**가 뜹니다(HTTP 503).

처음 실행 시 프론트엔드 패키지를 자동으로 설치합니다(1분 내외). 수동으로 하려면:

```bash
python -m pip install -r requirements.txt
```

```bash
cd frontend && npm install --omit=optional
```

두 서버를 따로 띄우려면:

```bash
python -m uvicorn api:app --port 8000
```

```bash
cd frontend && npm run dev
```

> Node.js 18 이상이 필요합니다. `--omit=optional` 은 이미지 최적화용 `sharp` 를 빼기 위한
> 것으로, 이 앱은 쓰지 않으며 제외하면 알려진 취약점 경고도 함께 사라집니다.

해시 탭이 아니라 **실제 라우트**입니다. 새로고침·뒤로가기·즐겨찾기가 모두 정상 동작합니다.

| 경로 | 화면 | 로그인 |
|---|---|---|
| `/` | 분석 — 종목 검색, 개장 예측, 시평선, 차트, 지표 19종, 뉴스·커뮤니티 | 불필요 |
| `/score` | 성적표 — AI 적중/오답 집계 + **실시간 중간채점**(오른쪽에 종목 시세) | **필요** |
| `/paper` | 모의투자 — **시장가·지정가 주문**, 차트, 미체결·보유·거래내역 | **필요** |
| `/autotrade` | **자동매매 콘솔** — 주식·ETF·선물·옵션 자동 진입/청산, 리스크 한도, 백테스트 | **필요** |
| `/login` | 로그인 · 회원가입 | — |

> 자동매매 콘솔은 백엔드(8000번)가 직접 그리는 단독 화면이라 **웹(3000번)이 꺼져
> 있어도 열립니다.** 돌아가는 자동매매를 멈추려는데 화면이 안 뜨면 그게 사고이기
> 때문입니다. 자세한 사용법은 [AUTOTRADE.md](AUTOTRADE.md).

## 로그인 · 계정별 데이터

계정마다 **예측 기록·성적표·모의투자 계좌·관심종목**이 따로 저장됩니다.
같은 종목을 봐도 성적과 잔고는 계정별로 독립적입니다.

| 항목 | 방식 |
|---|---|
| 비밀번호 | PBKDF2-HMAC-SHA256 · 20만 회 · 계정별 salt (평문 미저장) |
| 세션 | 무작위 토큰 30일, 만료 시 자동 정리 |
| 전달 | `Authorization: Bearer` 헤더 + 쿠키 |
| 분리 | `predictions` · `paper_*` · `watchlist` 전 테이블에 `user_id` |

로그인 도입 이전에 쌓인 데이터는 **'이전 기록'** 계정으로 자동 귀속되어 사라지지 않습니다.

### 보고 있던 종목이 유지됩니다

한 번 검색한 종목은 페이지를 옮기거나 브라우저를 닫았다 열어도 그대로 남습니다.
저장 위치는 `localStorage` + 주소창의 `?q=` 두 곳이고, **주소창이 우선**입니다
(링크로 받은 종목을 존중하기 위함). 조회에 **성공한** 종목만 기억하므로,
오타로 실패한 문자열이 저장돼 다음 방문마다 "종목 없음"이 뜨는 일은 없습니다.

## 실시간 중간채점

확정 채점은 만기(10분~1일)가 지나야 나옵니다. 그동안 성적표가 비어 보이지 않도록,
`/score` 오른쪽에 **지금 보고 있는 종목**과 진행 중인 예측을 함께 띄웁니다.

```
GET /api/scorecard/live?ticker=005930
```

| 표시 | 내용 |
|---|---|
| 종목 시세 | 현재가·등락률, 가격이 바뀌면 깜빡임 |
| 잠정 집계 | 맞는 중 / 틀리는 중 / 보합 + 잠정 적중률 |
| 진행 중 예측 | 시평선별 기준가 → 현재가, 변화율, 만기 카운트다운 |

갱신 주기는 장중 5초 · 장 마감 30초입니다. 카운트다운은 서버를 다시 부르지 않고
브라우저에서 1초마다 흐르며, 응답에 실린 `server_time` 으로 시계 차이를 보정합니다.

> **잠정치입니다.** 만기까지 가격이 뒤집히면 결과도 뒤집히며, 위쪽 성적표의
> 적중률 통계에는 **들어가지 않습니다**. 확정 채점만 반영됩니다.

### 보합 판정 — 호가 단위보다 작은 차이는 무시

야후는 가격을 float32 로 내려주어 `$304.61` 이 `304.6099853515625` 로 들어옵니다.
이 차이(상대오차 5×10⁻⁸)를 상승으로 읽으면 **아무것도 움직이지 않은 예측이 전부
적중으로 기록됩니다**. 확정 채점과 실시간 채점 모두 `backtest.price_moved()` 를 써서
상대오차 10⁻⁶ 이하를 보합으로 처리합니다 — 어떤 시장의 호가 단위보다도 작은 값입니다.

## 모의투자 — 트레이딩 데스크

종목을 고르면 **시세 → 차트 → 주문표**가 한 화면에 뜹니다. 증권사 프로그램의 흐름 그대로입니다.

### 실시간 주문 금액

수량이나 지정가를 입력하는 즉시 총액을 다시 계산합니다. 수수료·거래세까지 더한
**실제로 나가는 돈**이라, 주문을 넣기 전에 얼마가 빠지는지 알 수 있습니다.

```
수량 10주 → 주문단가 239,500원 · 주문금액 2,395,000원 · 수수료 359원
                                        총 매수금액 2,395,359원
```

`10% / 25% / 50% / 최대` 버튼으로 주문가능 금액 기준 수량을 바로 채울 수 있고,
한도를 넘기면 주문 버튼이 잠깁니다.

### 시장가 · 지정가

| 유형 | 동작 |
|---|---|
| **시장가** | 조회 시점의 현재가로 즉시 체결 |
| **지정가** | 미체결로 대기하다 조건에 닿으면 체결 — 매수는 현재가 ≤ 지정가, 매도는 현재가 ≥ 지정가 |

지정가는 접수 직후에도 한 번 검사하므로, 이미 조건을 만족하는 주문(현재가보다 높게 건
매수 등)은 그 자리에서 체결됩니다. 체결가는 **지정가가 아니라 실제 현재가**입니다 —
지정가보다 유리하게 체결되는 경우가 그대로 반영됩니다.

### 호가 단위

아무 숫자나 받으면 실제 시장에 낼 수 없는 주문이 됩니다. 국내는 KRX 호가 단위표
(2023-01 개편)에 맞춰 자동 정렬하고, `−/＋` 버튼은 한 호가씩 움직입니다.

```
239,537 입력 → 239,500   (20만~50만원 구간, 500원 단위)
  4,321 입력 →   4,320   (2천~5천원 구간, 5원 단위)
1,234,567 입력 → 1,235,000 (50만원 이상, 1,000원 단위)
```

### 예수금·수량 구속

지정가 주문을 걸면 그만큼 **예수금이 묶입니다**. 묶지 않으면 100만원으로 100만원짜리
지정가 매수를 열 번 걸 수 있고, 그게 다 체결되면 잔고가 음수가 됩니다. 매도도 같은
이유로 보유 수량을 묶습니다.

```
주문가능 현금 = 예수금 − 미체결 매수 구속액
주문가능 수량 = 보유 수량 − 미체결 매도 구속량
```

주문을 취소하면 즉시 풀립니다. 계좌 초기화는 미체결 주문까지 함께 정리합니다.

### 주문 수량은 깎지 않습니다

5주 매도 주문에 3주만 체결시키는 것은 사용자가 낸 주문과 **다른 주문**을 대신 내주는
것입니다. 주문가능 수량을 넘으면 반려합니다. 수량을 비우면 '주문가능 전량'입니다.

## 존재하지 않는 종목 처리

입력한 종목이 실제로 상장돼 있지 않으면 **분석을 수행하지 않고 명시적으로 거부**합니다.
추정치나 예시 데이터로 대체하지 않습니다.

```
$ python main.py predict 없는회사
❌ '없는회사' 라는 이름의 상장 종목을 찾을 수 없습니다.

$ python main.py predict APPL
❌ 티커 'APPL' 로 상장된 종목을 찾을 수 없습니다.  비슷한 티커를 확인해 보세요.
   혹시 이 종목인가요?
     · Apple Inc. (AAPL, 미국)
     · Applied Materials, Inc. (AMAT, 미국)
```

API는 HTTP **404** 와 함께 다음을 반환하고, 웹/확장프로그램은 전용 "종목 없음" 화면을 띄웁니다.

```json
{ "error": "SYMBOL_NOT_FOUND", "query": "APPL",
  "message": "티커 'APPL' 로 상장된 종목을 찾을 수 없습니다.",
  "suggestions": [{ "key": "AAPL", "name": "Apple Inc.", "market": "US" }] }
```

**실존 확인 경로** (`data_sources/symbol_registry.py`)

1. **한국** — KRX(KIND) 상장법인 목록 약 2,700종목을 내려받아 `.cache/krx_symbols.json` 에 3일 TTL로 캐시.
   캐시에 없는 코드는 토스증권 / 네이버금융 API로 직접 조회해 2차 확인.
2. **미국** — Yahoo Finance 심볼 검색에서 **정확히 일치하는** 심볼이 있을 때만 인정.

네트워크가 끊겨도 캐시가 있으면 만료된 캐시로 계속 동작합니다.

## 실시간 시세

대시보드는 `GET /api/quote/{query}` 를 주기적으로 호출해 **현재가·등락률·확률을 실시간 갱신**합니다.

| 상황 | 폴링 주기 |
|---|---|
| 장중 | 4초 |
| 장 마감 / 주말 | 60초 |
| 요청 실패 | 3초 후 재시도 |
| 배경 탭 | 중단 (탭 복귀 시 즉시 갱신, 단 최초 1회는 항상 조회) |

갱신되는 것

- 현재가 (변동 시 상승=빨강 / 하락=파랑으로 깜빡임)
- 등락률·전일대비 금액
- **확률** — 마지막 일봉의 종가·고가·저가를 현재가로 갈아끼운 뒤 기술 지표를 다시 계산하므로,
  가격이 움직이면 확률도 따라 움직입니다
- **차트의 마지막 캔들** — 장중에 봉이 자라는 것을 볼 수 있습니다
- 부엉이 방향, 시세 카드의 현재가/등락률

### 장 상태 표시

가격이 안 움직이는 게 "고장"인지 "장 마감"인지 구분되도록 현재 장 상태를 항상 표시합니다
(`data_sources/market_clock.py`). 한국 09:00~15:30, 시간외 16:00~18:00, 미국은 KST 환산 기준.
공휴일 달력은 포함하지 않아 공휴일에는 "장중"으로 보일 수 있으므로, 마지막 체결 시각을 함께 띄웁니다.

### 성능

`/api/quote` 는 가격만 실시간으로 받고 뉴스·커뮤니티·일봉은 **3분 TTL 캐시**를 재사용합니다.
`/api/predict` 가 이미 받아온 데이터를 캐시에 미리 넣어두므로(cache warming) 첫 폴링부터
빠릅니다. 실측 응답 **0.24초**.

### 토스증권 Open API 가 특히 중요한 이유

**장 운영 캘린더(`/api/v1/market-calendar/KR|US`)를 제공합니다.** 기존에는 장 시간을
코드에 하드코딩해 두어 **공휴일에 "장중"으로 잘못 표시**됐습니다. 이 API를 연결하면
공휴일·임시휴장까지 정확히 반영됩니다. 대시보드에 판정 출처가 함께 표시됩니다.

```
장 상태 출처: 토스 공식 캘린더        ← 키 설정 시
장 상태 출처: 내장 시간표 (공휴일 미반영)  ← 키 미설정 시
```

종목 마스터에 상장폐지일·거래정지 여부가 들어 있어 실존 검증도 정확해지고,
최대 200종목을 한 번에 조회할 수 있어 감시목록 갱신이 빨라집니다.

> 토스 공식 API가 지원하는 캔들은 **1분봉과 일봉뿐**입니다. 주봉·월봉·년봉은
> 네이버 경로를 그대로 씁니다. 커뮤니티(댓글) API는 제공하지 않으므로
> 토스 커뮤니티는 확장프로그램 스크랩으로 수집합니다.

### 연동할 수 없었던 것

| 요청 | 결과 |
|---|---|
| 카카오페이증권 API | 개발자센터는 **결제 전용** — 증권 데이터 API 없음 |
| 팍스넷 API | 개발자 포털 도메인 자체가 존재하지 않음 |

두 곳은 **확장프로그램 스크랩**으로 커버합니다.

## 증권사 공식 API 상세 (한국투자증권 KIS)

네이버/토스는 서비스 내부용 비공식 엔드포인트라 언제든 막힐 수 있습니다.
한국투자증권은 개인 개발자에게 **공식 REST API**를 무료로 제공하므로, 키를 넣으면 이쪽을
우선 사용합니다.

```
아테나.bat  →  [7] API 키  →  한국투자증권 KIS
```

키 입력을 안내하고 `api_keys.json` 에 저장합니다. 수동 설정도 가능합니다.

```bash
set KIS_APP_KEY=발급받은_APP_KEY
```

```bash
python -m data_sources.kis_client
```

두 번째 명령은 연결 자체 점검입니다 (토큰 발급 → 현재가 → 투자자별 매매동향 → 일봉 순).

**KIS를 쓰면 좋아지는 점**

| | 네이버/토스 (기본) | 한국투자증권 KIS |
|---|---|---|
| 약관 | 비공식 내부 API | 공식 개발자 API |
| 현재가 | 실시간 | 실시간 |
| 투자자별 매매동향 | **전일 확정치** | **장중 갱신** |
| 안정성 | 구조 변경 시 중단 가능 | 버전 관리됨 |

키를 넣지 않아도 기존 경로로 전부 정상 동작합니다. 대시보드 상단 배너에 현재 어느 소스를
쓰는지 표시됩니다.

> 이 어댑터는 KIS 공식 문서의 스펙(tr_id, 필드명)에 맞춰 작성했지만, 실제 계정 키로 응답을
> 검증하지는 못했습니다. 키를 발급받은 뒤 위 자체 점검을 먼저 돌려보세요.

## 스크랩 (브라우저 경유 수집)

서버에서 직접 접근이 막힌 커뮤니티를 **크롬 확장프로그램이 사용자 브라우저에서 읽어**
로컬 서버로 보냅니다.

| 소스 | 서버 직접 접근 | 확장프로그램 경유 |
|---|---|---|
| 토스증권 커뮤니티 | ❌ 401/405 | ✅ |
| 팍스넷 종목토론방 | ❌ 404 | ✅ |
| 카카오페이증권 | ❌ 연결 거부 | ✅ |
| 네이버 종목토론방 | ✅ | ✅ (보강) |

```
사용자가 토스 종목 페이지 방문
      → scraper.js 가 화면의 공개 게시글 제목을 읽음
      → POST http://localhost:8000/api/scrap
      → 커뮤니티 여론 계산에 병합
```

**지키는 원칙**

- 사용자가 직접 연 종목 페이지에서만 동작합니다 (자동 순회 없음)
- 화면에 이미 렌더링된 공개 게시글 제목만 읽습니다
- 로그인 정보·쿠키·개인정보는 읽지도 보내지도 않습니다
- 전송 대상은 **사용자 PC의 localhost 뿐**입니다 (외부 서버로 나가지 않음)
- 같은 글은 지문(fingerprint)으로 한 번만 집계하고, 12시간이 지나면 만료됩니다

수집 현황은 `GET /api/scrap/{종목}` 으로 확인할 수 있습니다.

> 각 사이트의 DOM 구조는 예고 없이 바뀝니다. 셀렉터가 안 맞으면 조용히 아무것도 보내지
> 않고 넘어가므로(브라우징 방해 금지), 수집이 안 되면 해당 사이트에서 개발자도구로
> 게시글 요소를 확인해 `extension/scraper.js` 의 `ADAPTERS` 셀렉터를 조정하세요.

## 기술적 지표 (근거 기반)

`engine/indicators.py` 는 지표를 "숫자 하나"로 뭉개지 않고, **지표별 계산값 + 판단 근거 문장 +
기여도**를 함께 반환합니다. 대시보드에서는 이게 그대로 표로 표시됩니다.

```
이동평균 5/20   -7.82%   5일선(258,600)이 20일선(280,525) 대비 -7.82% 아래에 있습니다.
                         단기 추세가 우하향입니다.
                         점수 -1.0 × 비중 1.2 | (5일선-20일선)/20일선 ÷ 5%      기여도 -1.20
```

| 지표 | 계열 | 비중 | 점수화 방식 |
|---|---|---|---|
| MACD(12,26,9) | 추세추종 | 1.2 | 히스토그램 ÷ (종가×1%), 최근 교차 시 ×1.3 |
| 이동평균 5/20 | 추세추종 | 1.2 | 이격률 ÷ 5% |
| RSI(14) | 되돌림 | 1.0 | ≤35 과매도(+), ≥65 과매수(−), 그 사이 0 |
| 모멘텀 ROC(10) | 추세추종 | 0.9 | 10일 등락률 ÷ 10% |
| 중기추세 20/60 | 추세추종 | 0.8 | 이격률 ÷ 10% (정배열/역배열) |
| 볼린저 %B(20,2σ) | 되돌림 | 0.8 | (0.5 − %B) × 2, 스퀴즈 여부 함께 표시 |
| 스토캐스틱(14,3,3) | 되돌림 | 0.7 | ≤20(+) / ≥80(−), %K·%D 교차 시 ±0.25 |
| 거래량(20일 평균 대비) | 확인 | 0.6 | sign(당일 등락) × clip((비율−1)/2, 0, 1) |
| OBV 추세(20일) | 추세추종 | 0.6 | 회귀 기울기 ÷ 평균거래량 ÷ 0.5 |
| 추세위치(120일) | 추세추종 | 0.5 | ((위치비율−0.5)×2)×0.8 |
| ATR(14) 변동성 | 참고 | **0.0** | 방향성이 없어 확률에 미반영, 리스크 표시용 |

**기술 종합점수 = Σ(지표점수 × 비중) ÷ Σ(계산 성공한 지표의 비중)**

### 장 시작 전 예측 (메인)

대시보드 오른쪽에 크게 표시되는 **주 예측**입니다. "다음 정규장이 열릴 때 전일 종가 대비
위로 뜰 것인가"를 계산합니다.

시평선 예측(10분~1일)과 **별도 공식**을 쓰는 이유는 시가 갭의 동인이 다르기 때문입니다.

```
raw = w기술 × 기술점수 × 0.85     ← 일봉 기술신호는 갭보다 세션 중 흐름을 설명
    + w뉴스 × 뉴스점수 × 1.35     ← 밤사이 뉴스가 갭의 주 동인
    + w커뮤 × 커뮤점수 × 1.00

확률 = 100 / (1 + e^(−4 × raw))
```

장이 닫힌 동안 분봉 신호는 의미가 없으므로 **아예 쓰지 않습니다.**

화면에는 이 공식이 **실제 수치로 전개되어** 표시됩니다.

```
기술 = 0.525 × -0.3809 × 0.85  =  -0.1700
뉴스 = 0.285 × +0.0396 × 1.35  =  +0.0152
커뮤 = 0.190 × +0.2000 × 1.00  =  +0.0380
                    raw 합계   =  -0.1167
확률 = 100/(1 + e^(−4.0 × −0.1167)) = 38.5% 상승  →  61.5% 하락
```

QA에서 각 항이 `가중치 × 점수 × 배수`로 재현되는지, 세 항의 합이 `raw`와 일치하는지
항등성을 검사합니다 (화면 표시와 실제 계산이 어긋나지 않도록).

> `news_amplifier` 1.35, `technical_damping` 0.85 는 `config.OPEN_PREDICTION` 에서
> 조정할 수 있습니다. 이론값이 아니라 설계 판단값이며, 시가 방향 적중률이 쌓이면
> 그 결과로 교체하는 것이 옳습니다.

### 예측 시평선 6종 (보조)

**10분 / 1시간 / 6시간 / 12시간 / 18시간 / 1일 뒤** 를 각각 예측합니다.
시평선마다 다른 확률이 나오는 이유는 두 가지입니다.

1. **기술점수 배합** — 짧은 시평선은 분봉 기반 점수를, 긴 시평선은 일봉 기반 점수를
   더 많이 씁니다 (10분 뒤는 분봉 85%, 1일 뒤는 12%).
2. **신뢰도 감쇠** — 초단기는 호가 노이즈가 커서 신뢰도를 낮게 잡아 확률이 50%에
   가까워집니다.

```
10분 뒤    50.8%    분봉비중 85%   신뢰도 0.55
1시간 뒤   50.7%    분봉비중 70%   신뢰도 0.70
6시간 뒤   54.4%    분봉비중 45%   신뢰도 0.85
12시간 뒤  57.3%    분봉비중 30%   신뢰도 0.95
18시간 뒤  59.3%    분봉비중 20%   신뢰도 1.00
1일 뒤     60.6%    분봉비중 12%   신뢰도 1.00
```

> `intraday`/`conf` 수치는 이론적으로 유도된 상수가 아니라 **설계 판단값**입니다.
> `config.PREDICTION_HORIZONS` 에서 조정할 수 있으며, backtest로 시평선별 적중률이
> 쌓이면 그 결과로 교체하는 것이 옳습니다.

### 실시간 적중 판정

장중에 "지금 예측이 맞고 있는지"를 바로 보여줍니다 (`GET /api/verify/{query}`).
오늘 저장된 예측 중 가장 이른 것(= 개장 무렵 판단)을 현재가와 비교합니다.

```
예측 적중 중 — 하락 방향이 맞고 있습니다

개장 무렵 61.5% 확률로 하락을 예상했습니다. 현재가 207,000은 전일 종가 208,500 대비
-0.72%로 하락 중입니다. 맞춘 요소는 기술적 지표입니다. 틀린 요소는 뉴스 감성,
커뮤니티 여론입니다.

  맞음  기술적 지표는 -0.409로 하락을 가리켰고, 실제는 하락이라 맞았습니다.
  틀림  뉴스 감성은 +0.091로 상승을 가리켰고, 실제는 하락이라 틀렸습니다.
  틀림  커뮤니티 여론은 +0.300로 상승을 가리켰고, 실제는 하락이라 틀렸습니다.
```

요소별로 "혼자 예측했다면 맞았을지"를 따로 채점하므로, **무엇이 이 종목에서 잘 통하는지**가
쌓입니다. 가격이 전일 종가를 넘나들면 판정이 뒤집히므로 시세 5회마다 다시 계산합니다.

장이 닫혀 있으면 마지막 체결가 기준임을 명시합니다. 정식 채점(DB 기록)은 여전히
`python main.py close` 로 이뤄집니다.

| **분봉** | 네이버 `/minute` | Yahoo `1m` | 미국은 최근 5거래일까지만 보관 |
| **일봉** | 네이버 `/day` | Yahoo `1d` | 확률 계산의 기준 |
| **주봉** | 네이버 `/week` | Yahoo `1wk` | |
| **월봉** | 네이버 `/month` | Yahoo `1mo` | |
| **년봉** | 네이버 `/year` | Yahoo 월봉 재집계 | 삼성전자 1990년~ |

```

```

RSI·MACD·볼린저·이동평균은 **선택한 주기의 시계열로 다시 계산**됩니다. 즉 월봉을 고르면
월봉 RSI가 나옵니다. 다만 화면 상단의 **확률은 항상 일봉 기준**입니다 (주기마다 예측을
따로 만들지는 않습니다).

**초봉이 특별한 이유** — 초 단위 과거 데이터를 주는 무료 공개 API가 없습니다. 그래서
페이지가 켜져 있는 동안 들어오는 실시간 시세를 초 단위로 직접 쌓아 캔들을 만듭니다.
따라서 접속한 시점부터의 흐름만 보이고, 새로고침하면 초기화됩니다. 표본이 적어
RSI·MACD·볼린저는 계산하지 않고 이동평균만 표시합니다.
(진짜 체결 단위 데이터가 필요하면 KIS 웹소켓 `실시간체결가` 연동이 필요합니다.)

### 일봉 차트

대시보드에는 지표 점수가 어떤 가격 흐름에서 나왔는지 확인할 수 있도록 **캔들차트**가 함께
그려집니다 (`GET /api/chart/{query}`). 외부 차트 라이브러리 없이 인라인 SVG로 직접 그리므로
오프라인에서도 동작합니다.

- 캔들(양봉 빨강 / 음봉 파랑) + 5·20·60일 이동평균 + 볼린저밴드 음영
- 거래량 / RSI(14, 30·70 기준선) / MACD(12,26,9 히스토그램+시그널) 보조 패널
- 마우스를 올리면 해당 날짜의 시·고·저·종가, 전일대비, 거래량, RSI, MACD를 툴팁으로 표시
- 60일 / 120일 / 240일 기간 전환

차트에 쓰이는 RSI·MACD는 점수 계산에 쓰는 함수와 **같은 파라미터**(Wilder EMA 방식 RSI,
12/26/9 MACD)로 계산해 화면과 점수가 어긋나지 않게 했습니다. 이동평균 워밍업을 위해 요청
구간보다 80봉을 더 받아 계산한 뒤 잘라내므로, 60일선도 차트 첫날부터 그려집니다.

되돌림형 지표는 극단 구간에서만 신호를 내도록 설계해(중립 구간은 0) 추세추종형 지표와
서로 상쇄되지 않게 했습니다. 비중은 `config.INDICATOR_WEIGHTS` 에서 조정합니다.

일봉이 20개 미만이면(신규 상장·거래정지 이력 등) 기술점수를 억지로 만들지 않고 0(중립)으로
처리하고 그 사유를 화면에 표시합니다.

## 국면 판별 (Regime Detection)

추세추종 지표(MACD·이동평균)와 평균회귀 지표(RSI·볼린저)는 서로 반대 신호를 내는 일이
잦습니다. 고정 가중치로 합치면 둘이 상쇄돼 신호가 뭉개집니다. 그래서 **먼저 국면을
판별하고, 그 국면에서 실제로 작동하는 지표군에 가중치를 몰아줍니다.**

판별 재료 — 서로 다른 각도에서 같은 질문을 봅니다.

| 통계량 | 출처 | 보는 것 |
|---|---|---|
| 분산비율 VR(5) | Lo & MacKinlay (1988) | 수익률에 자기상관이 있는가 (z통계량으로 유의성 검정) |
| Hurst 지수 | R/S 분석 + Anis-Lloyd(1976) 편향보정 | 시계열이 지속적인가 반지속적인가 |
| ADX | Wilder (1978) | 방향성 추세의 강도가 있는가 |
| OU 반감기 | Ornstein-Uhlenbeck AR(1) | 평균으로 돌아오는 데 걸리는 기간 |

| 국면 | 추세추종 배수 | 평균회귀 배수 |
|---|---|---|
| 추세 국면 | ×1.45 | ×0.55 |
| 평균회귀 국면 | ×0.55 | ×1.45 |
| 방향성 불분명 | ×0.8 | ×0.8 |

**Anis-Lloyd 보정이 중요한 이유** — R/S 분석은 소표본에서 H를 과대추정합니다.
보정 전에는 순수 랜덤워크조차 H=0.639가 나와 "추세 지속"으로 오판했습니다.
보정 후 0.513으로 교정됩니다 (몬테카를로 25회 평균, `tests/test_qa.py`에서 검증).

## 기술적 지표 19종

| 계열 | 지표 |
|---|---|
| 추세추종 | MACD, 이동평균 5/20, 중기추세 20/60, ROC, OBV, 추세위치, **ADX/DMI**, **Aroon**, **회귀추세(기울기×R²)** |
| 평균회귀 | RSI, 볼린저 %B, 스토캐스틱, **CCI**, **Williams %R** |
| 수급확인 | 거래량비, **MFI**, **CMF** |
| 참고(가중치 0) | ATR, **Yang-Zhang 변동성** |

**Yang-Zhang 변동성** (Yang & Zhang 2000) 은 시가·고가·저가와 밤사이 갭까지 반영해
종가만 쓰는 방식보다 같은 표본에서 훨씬 안정적입니다. 갭이 잦은 국내 종목에 유리합니다.

## 확률 공식 (Athena Score)

```
raw = w_기술 × 기술점수 + w_뉴스 × 뉴스점수 + w_커뮤니티 × 커뮤니티점수
확률(%) = 100 / (1 + e^(-4 × raw))
```

초기 가중치는 기술 50% / 뉴스 30% / 커뮤니티 20% (`config.INITIAL_WEIGHTS`)이며,
`python main.py close` 실행 시마다 각 요소의 "단독 적중률"을 계산해서
**랜덤(50%)보다 확실히 더 잘 맞춘 요소만** 가중치를 서서히 더 가져갑니다.
(표본이 20건 미만이거나 모든 요소가 랜덤 수준이면 가중치를 바꾸지 않습니다.)

## 예측 기록과 채점

**기록** — 같은 종목·시평선의 미채점 예측이 15분 안에 있으면 새로 쌓지 않고 갱신합니다.
대시보드가 4초마다 폴링하므로 이 장치가 없으면 트랙레코드가 단순 조회 횟수로 부풀어
통계가 무의미해집니다. 예측마다 **만기 시각(`target_at`)과 기준가(`base_price`)** 를
함께 저장합니다.

**채점** — `python main.py close 종목명` 은 **만기가 지난 예측만** 각자의 시평선 기간으로
채점합니다.

| 시평선 | 사용 데이터 | 비교 대상 |
|---|---|---|
| 10분 ~ 18시간 | 분봉 | 예측 시점 가격 → 만기 시점 가격 |
| 1일 | 일봉 | 예측 시점 가격 → 만기 시점 가격 |

- 만기 시점 시세가 아직 없으면(휴장·지연) 채점을 **보류**하고 다음 실행으로 넘깁니다
- 가격이 정확히 같으면 **채점에서 제외**합니다 — `final >= base` 로 판정하면 무변동이
  전부 '상승 적중'이 되어 통계가 상승 쪽으로 편향되기 때문입니다
- 만기 지난 것만 다루므로 하루에 여러 번 실행해도 안전합니다

적중률은 **시평선별로 따로** 집계합니다. 10분 예측과 1일 예측은 재는 대상이 달라
하나로 뭉치면 해석할 수 없기 때문입니다.

### 뉴스 감성 점수화

제목에 등장한 표현의 가중합을 `tanh(합 / 2)` 로 눌러 -1~1 로 만듭니다.

```
"Top Pick"                              -> +0.245   (약한 표현 1개)
"Stock Surges After Beating Estimates"  -> +0.740
"Record Surge Beat Upgrade Rally Soar"  -> +0.991   (강한 표현 다수)
```

영어는 어간 + 어미(`-s/-es/-ed/-ing`) 정규식으로 매칭해 `Surging`·`Tumbling` 같은 활용형도
잡되, `top` 이 `topic` 에 걸리지 않도록 단어 경계를 강제합니다.

**관련성 가중** — 제목에 종목명/티커가 없는 기사(섹터 일반론)는 가중치 0.4배로 낮춥니다.
개별 종목 피드에도 무관한 기사가 섞여 들어오기 때문입니다.

### 레버리지 · 인버스 ETF 처리

`SOXS`(Semiconductor **Bear** 3X), `KODEX 200선물**인버스**2X` 같은 상품은 기초자산과
**반대로** 움직입니다. 그래서 종목명에서 인버스 여부와 배율을 판별한 뒤
(`symbol_registry.classify_etf`), **종목을 직접 언급하지 않은 섹터 뉴스의 부호를 뒤집습니다.**
상품명이 직접 나온 기사(`"SOXS Jumps 11%"`)는 그 상품 자체의 이야기이므로 뒤집지 않습니다.

화면 상단에는 레버리지/인버스 경고를 표시합니다 — 일일 수익률을 추종하는 구조상 장기 보유 시
기초지수와 크게 어긋날 수 있고(변동성 끌림), 뉴스 신호 신뢰도도 일반 종목보다 낮기 때문입니다.

### 표본 확신도 보정

뉴스와 커뮤니티 점수에는 표본 수 기반 감쇠가 걸려 있습니다.

- **뉴스** — 감성이 잡힌 기사 수 ÷ 5 (최대 1.0)를 곱함.
  기사 12건 중 1건만 부정 키워드에 걸렸다면 그건 "뉴스가 부정적"이 아니라 표본이 적은 것에 가깝습니다.
- **커뮤니티** — 방향성이 분류된 글 수 ÷ 10 (최대 1.0) 만큼만 중립(0.5)에서 벗어나게 함.
  40건 중 4건만 분류됐다면 "여론 75% 매수"가 아니라 표본 4건일 뿐입니다.

감쇠를 안 걸면 게시글 몇 건이 확률을 크게 흔듭니다. 보정 내용은 근거 패널에 그대로 표시됩니다.

## 화면 구성 (3개 탭)

### 분석
종목 검색, 장 시작 전 예측, 시평선 6종, 캔들차트(초·분·일·주·월·년),
기술 지표 19종, 국면 판별, 뉴스·커뮤니티 피드, 실시간 적중 판정.

### 성적표
AI가 지금까지 **얼마나 맞췄는지** 실제 채점 결과입니다.

```
채점 완료 124   맞춘 예측 68   틀린 예측 56   적중률 54.8%   채점 대기 36
```

- **자동 채점** — 서버가 10분마다 만기가 지난 예측을 자동으로 채점합니다.
  `main.py close` 를 잊어도 성적이 쌓입니다. [지금 채점] 버튼으로 즉시 실행도 가능합니다.
- **시평선별 · 종목별 적중률** — 어떤 구간과 어떤 종목에서 잘 맞추는지 따로 봅니다.
- **채점 상세** — 예측 방향·확률 → 실제 방향, 그리고 **가격이 얼마에서 얼마로 움직였는지**
  까지 한 줄씩 기록합니다.

**무효 처리** — 장 마감 후에 낸 10분 예측처럼 만기 구간에 거래가 아예 없었던 예측은
시간이 더 지나도 채점될 수 없습니다. 6시간이 지나면 '무효'로 정리해 대기열에서 빼고,
적중률 통계에는 포함하지 않습니다.

### 모의투자 (가상머니)
가상 자금 1,000만원으로 실제처럼 매매합니다. **실제 주문은 절대 나가지 않습니다.**

적중률(%)만으로는 "그래서 돈을 벌었나"를 알 수 없습니다. 방향을 60% 맞춰도 틀릴 때
크게 잃으면 손실입니다. 모의투자는 신호를 실제로 따라갔을 때의 손익을 보여줍니다.

| 항목 | 내용 |
|---|---|
| 거래 비용 | 국내 수수료 0.015% · **매도 시 거래세 0.18%** · 미국 0.25% |
| 통화 | 원화 단일 계좌 — 미국 종목은 **실시간 환율로 원화 환산**해 거래 |
| 손익 | 평가손익(미실현)과 실현손익을 분리해 표시 |
| 주문 | 매수는 금액 지정(수수료 감안해 최대 수량 계산), 매도는 수량 또는 전량 |

> 원화 계좌에 달러 가격을 그대로 넣으면 100만원으로 AAPL 3,229주(약 14억원어치)를
> 사는 일이 생깁니다. 실제로 이 버그가 있었고, 환산 계층(`data_sources/fx.py`)을
> 넣어 고쳤습니다. 환율은 토스 공식 API → Yahoo `KRW=X` 순으로 조회합니다.

## 화면 기능

**상단 카운트다운** — 다음 장 세션까지 남은 시간을 초 단위로 표시합니다.
장중이면 점이 빨갛게 깜빡이고, 1시간 이내면 금색으로 바뀝니다.
한국/미국 종목에 따라 기준 시각이 자동으로 달라집니다.

**다크 / 라이트 테마** — 우측 상단 토글. 최초 방문 시 OS 설정을 따르고, 이후 선택은
`localStorage` 에 저장됩니다. 차트를 포함한 모든 색이 CSS 변수로 연결돼 있어 즉시 전환됩니다.

**올빼미 표정** — 확신도·방향·장 세션에 따라 달라집니다.

| 상태 | 표현 |
|---|---|
| 강한 상승 (≥65%) | 날개를 활짝 펴고 귀깃이 쫑긋, 눈썹 올라감, 동공 확대(6.4) |
| 약한 상승 | 날개 반쯤, 시선 위로 |
| 불확실 (<55%) | 동공 축소(3.6), 눈썹 수평 — 관망 |
| 강한 하락 (≥65%) | 날개 접고 웅크림, 미간 찌푸림, 부리 늘어짐 |
| 장 마감 | 눈 감고 수면, 귀깃 처짐, `zzz` 표시 |

장중에는 2.6~6.8초 간격으로 불규칙하게 눈을 깜빡이고(가끔 두 번 연속), 상승이면 위를,
하락이면 아래를 봅니다. 얼굴 원반·가슴 깃털·발톱 등 세부도 추가했습니다.

## API 엔드포인트

## 크롬 확장 프로그램

1. 크롬 주소창에 `chrome://extensions` 입력
2. 우측 상단 "개발자 모드" 켜기
3. "압축해제된 확장 프로그램을 로드합니다" 클릭 → `extension` 폴더 선택
4. 툴바 아이콘 클릭 → 종목명/코드 입력, 또는 토스증권·네이버금융 종목 페이지에서 자동 감지

자동 감지는 토스증권(`/stocks/A005930`)과 네이버금융(`?code=005930`) URL 패턴을 읽고,
실패하면 페이지 제목에서 종목명을 추출합니다. 백엔드가 종목명도 받아주므로 그대로 동작하며,
잘못 잡힌 값은 서버가 404로 걸러냅니다.

확장 프로그램도 API 서버(`localhost:8000`)가 켜져 있어야 동작합니다. 꺼져 있으면 추정치를
보여주지 않고 "서버 미연결" 안내를 표시합니다.

## exe로 패키징하기 (Windows)

1. `아테나.bat` → `[B] EXE 만들기` (최초 1회, 1~2분 소요)
2. `dist\AthenaSignal.exe` 생성됨
3. 이후 이 exe를 더블클릭 → 서버 시작 + 브라우저 자동 실행

`athena.db` 와 `.cache/` 는 **exe가 놓인 폴더**에 생성되므로 예측 기록이 재실행 후에도 남습니다.
exe를 옮길 때는 이 파일들도 같이 옮기면 기록이 유지됩니다.
